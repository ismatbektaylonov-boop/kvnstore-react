# Sanitized Stitch backend design brief

KVN Store fashion e-commerce. Designs must be usable polished real screens, not API documentation. Fictional products/people only. Mandatory Ocean Blue — Elegant Corporate: background #FFFFFF, secondary panels #F0F9FF, all main text/headings #0C2340, primary buttons/links/active nav #0F6B8F with white text, accents #38BDF8 with navy text. Inter typography, generous whitespace, subtle shadows, softly rounded 8–12px corners, visible keyboard focus, accessible contrast, 44px targets, reduced motion. Shared components: logo, store header Home/Catalog/Cart/Orders/Account, mobile menu and bottom navigation, product cards, image fallback, size chips, quantity stepper, form controls with inline errors, status badge, pagination, skeletons, empty panels, retry alerts, success toasts. Admin separate header/sidebar Products/Orders/Customers/Storefront/Logout; mobile drawer and stacked cards. No unsupported reviews, wishlist page, coupons, password recovery, analytics, tracking numbers, refunds action, email login or real payment. API notes belong to design annotations, never ordinary customer UI.

Exact inspected backend contracts (server root, no /api prefix): GET /auth/csrf -> {csrfToken}, credentials cookies on all auth/mutations; X-CSRF-Token on all unsafe methods. Customer auth is HttpOnly accessToken cookie (response token must not be stored); separate admin connect.sid session. Errors {code,message}, 400 validation,401 login,403 blocked/CSRF,404 missing,409 conflict,413 oversized,429 rate limit; handle pending and duplicate submission, expired session, retry.

Only PROCESS visible, no color or price-range filter. Product fields \_id 24hex, productName,productCollection,productPrice USD,productLeftCount global across sizes,productSizes[], legacy productSize/productShoeSize fallback,productDesc,productImages[],productViews,productLikes,isLiked,createdAt. Authenticated GET /cart -> {items:[{_id,productId,selectedSize,quantity,product|null,unitPrice|null,lineTotal|null,available}],subtotal,currency:'USD',checkoutReady}. DELETE /cart/items/:itemId, DELETE /cart return cart. Stored cart may contain unavailable products; unavailable must be removed/adjusted before checkout. No guest backend cart.
POST /cart/checkout {} with Idempotency-Key 8..128 alphanumeric,\_,- ->201 order snapshot; alternatively POST /order/create array [{productId,quantity,selectedSize}] with same key. Address read from saved memberAddress, must be nonblank. Customer edits address via profile before checkout; no card fields or delivery-method selector. Order status PENDING, unpaid,expiresAt30min; expiration cancels/restores stock. Replay same request key, never duplicate order after timeout. Show stock/cart-change409 and route to review.
GET /order/all?includeMeta=true&page&limit&orderStatus=PENDING|PAID|PROCESSING|SHIPPED|DELIVERED|CANCELLED ->{items,total,page,limit}; GET /order/:id own order -> {\_id,orderStatus,paymentMode:'unpaid'|'demo',expiresAt,paidAt,cancelReason:'customer'|'expired',orderSubtotal,orderShippingFee,orderTotal,refundedAmount,shippingAddress,orderItems:[{productId,productName,productImage,quantity,unitPrice,selectedSize}],createdAt}. POST /order/update {orderId,orderStatus:'CANCELLED'} only own PENDING ->updated order,409 otherwise. ## Final rendered-response clarification supplied to Stitch

GET /admin/user/all renders only member identifier, nickname, phone, and status; model fields such as address, avatar, points, description, and creation date are not available in this HTML response. GET /admin/order/all renders formatted date, status, customer nickname/phone, shipping address, item name/image/selection/quantity/line total and totals, but not paymentMode, expiresAt, paidAt, or refundedAmount. Keep unavailable fields out of admin designs and flag the missing JSON detail reads in handoff annotations. Own-order JSON has a different, richer contract.
