# KVN Store frontend contract

Source: sibling `../kvnstore/src` routers, controllers, services, validation, schemas and upload middleware, inspected 2026-11-09 and integrated with negotiated admin JSON on 2026-11-10. No environment files or private records were sent to Stitch.

The customer UI and preserved React Admin are now separate application builds. Admin rows below belong to `src/admin`, not the customer route tree. The existing EJS Admin remains in `kvnstore/src/views` and remains available alongside React administration. Both Admin interfaces use the same backend authorization and business rules. See [architecture](architecture.md).

| Screen                | Backend                                                                                       | Actions and constraints                                                                                                                                                                                                       |
| --------------------- | --------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Home / catalog        | `GET /product/all?includeMeta=true`, `/member/community?limit=4`                              | Search name (100 characters), collection, size, createdAt/views/price sorting, pagination. PROCESS products only. No color filter.                                                                                            |
| Product               | `GET /product/:id`, `POST /product/:id/like`                                                  | Like for authenticated members. Valid sizes only; global stock shared across sizes.                                                                                                                                           |
| Sign in / register    | `POST /member/login`, `/member/signup`                                                        | Nickname/password; registration also phone, optional saved address. No email. Password 8+ characters, at most 72 UTF-8 bytes.                                                                                                 |
| Account               | `GET /member/detail`, `POST /member/update`                                                   | Nickname, phone, address (500 characters each), description (2000), optional password and one image.                                                                                                                          |
| Cart                  | `GET /cart`, `PUT /cart/items`, `DELETE /cart/items/:itemId`, `DELETE /cart`                  | Server-persisted authenticated cart. PUT sets quantity. 1–20 per product across sizes, 50 lines maximum.                                                                                                                      |
| Checkout              | `POST /cart/checkout {}`                                                                      | Saved profile address required. Stable Idempotency-Key for retries. Server computes USD totals, $5 shipping below $100, free from $100.                                                                                       |
| Confirmation / orders | `GET /order/all?includeMeta=true`, `GET /order/:id`, `POST /order/update`                     | Only pending orders may be customer-cancelled. Orders reserve stock for 30 minutes.                                                                                                                                           |
| Demo payment          | `POST /order/:id/demo-pay {outcome?: success\|declined}`                                      | Separate demo checkout: approval marks PAID; decline returns 402 and preserves the unpaid reservation for retry. Explicit nonproduction flags required; no card collection or gateway.                                        |
| Admin entry           | `GET /admin/login`, `POST /admin/login`, `GET /admin/check`                                   | Separate session; JSON login returns {member}, JSON logout returns {logout:true}; HTML redirects remain available. No public admin registration.                                                                              |
| Admin products        | `GET /admin/product/all` (JSON/HTML), `POST /admin/product/create`, `POST /admin/product/:id` | JSON `{items}` with Accept application/json; original HTML remains available. Create uploads 1–5 images. Edit name, collection, price, stock, sizes, description, PAUSE/PROCESS/DELETE status. Image replacement unsupported. |
| Admin customers       | `GET /admin/user/all` (JSON/HTML), `POST /admin/user/edit`                                    | ACTIVE/BLOCK/DELETE status only; no role editing.                                                                                                                                                                             |
| Admin fulfillment     | `GET /admin/order/all` (JSON/HTML), `POST /admin/order/:id/status`                            | PAID → PROCESSING → SHIPPED → DELIVERED only. No admin payment/cancellation/refund.                                                                                                                                           |

Administrator login/logout additionally support JSON `{member}` / `{logout:true}` when requested with `Accept: application/json`; HTML redirects remain unchanged. Products, users and order lists return JSON `{items}` for the React client, protected by the existing active ADMIN session. All administration responses use no-store and Vary: Accept.

Local URLs: API `http://localhost:4003`, storefront `http://localhost:3000`, React admin `http://localhost:3002/administration`. Both apps use `REACT_APP_API_URL`; `REACT_APP_ADMIN_URL` and `REACT_APP_STOREFRONT_URL` link between the apps. EJS remains at `http://localhost:4003/admin`. Backend `FRONTEND_ORIGINS` must include both exact React origins.

All mutations require session-bound CSRF obtained from `GET /auth/csrf` and passed as `X-CSRF-Token`; all authenticated calls include cookies. Customer accessToken is HttpOnly; credentials/tokens are never stored by the frontend. Errors are `{code,message}`. Only application/json responses are parsed as JSON; older-server HTML responses use an explicit inert compatibility reader. Uploads accept JPEG/PNG/WebP, 5 MiB per image, 32 million decoded pixels. Media paths resolve against the backend origin.

## Implementation limits

No production payment gateway, recovery email, separate wishlist collection, coupons, tax calculation, shipment tracking, refund actions, or analytics endpoints exist. Reviews are implemented; favorites reuse the existing product-like relation. Authenticated admin JSON list APIs were added on 2026-11-10. The frontend now prefers authenticated JSON for product, order, customer and review collections and JSON session login/logout. Inert HTML readers remain only for compatibility with older servers. Customer profiles and order payment/expiry/refund details are read from actual JSON fields, with existing business actions unchanged. No fabricated records or metrics are used.

## Storefront expansion

The homepage retains its hero/category cards and adds independently loaded **New Arrivals**, **Most Viewed**, About KVN Store, and a Community preview. Recently Viewed is available through the signed-in account area rather than Home. The demo/unpaid backend has no trusted production payment signal: there is no Best Sellers claim or sales ranking. Most Viewed excludes zero-view cards. New Arrivals has no age badge because no age rule is configured.

| Surface                           | API / behavior                                                                                                                                                                      |
| --------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Home New Arrivals                 | `GET /product/all?includeMeta=true&order=createdAt&sort=desc&limit=8`; View all uses `/products?order=createdAt&sort=desc`                                                          |
| Home Most Viewed                  | `GET /product/all?includeMeta=true&order=productViews&sort=desc&limit=8`; View all keeps that sort in the existing catalog                                                          |
| Home Community / `/community`     | `GET /member/community?limit=4` / `limit=12`; public nickname, avatar, rank and stable key only                                                                                     |
| Account / product Recently Viewed | `GET /product/cards?ids=...`; signed-in only, max six IDs from the current account's browser history; active cards in client order; never calls detail endpoints to resolve history |
| `/favorites`                      | Protected route, safe `/login?next=...` return; `GET /product/favorites?page=1&limit=12`                                                                                            |
| Product-card and detail hearts    | Existing CSRF-protected `POST /product/:id/like`; shared pending, selected state and count; removal refreshes favorites and corrects an exhausted page                              |
| Product reviews                   | `GET /product/:id/reviews?page=1&limit=10`; newest first; `total` and `averageRating` cover all public reviews, not only the current page                                           |
| Own review                        | Private `GET /product/:id/reviews/me` returns a review or `null`; `PUT` sends only `{ rating, comment }`; `DELETE` removes public display and rating contribution                   |
| `/administration/reviews`         | Admin-session guard; `GET /admin/reviews?page=1&limit=20&visibility=hidden`; `POST /admin/reviews/:id/visibility` sends `{ visibility }` through the credentialed CSRF admin client |

`ProductCarousel` composes the shared product card, native horizontal scrolling/swipe, focusable track, previous/next controls, end disabling, overflow detection and reduced motion. About uses the existing everyday-layers campaign image, factual editable copy and catalog/guide links. The current typography and Ocean Blue palette remain in use.

Recently Viewed is removed from Home and opens inside the protected account layout at `/account/recently-viewed`. The profile sidebar lists **Your Orders**, **Favorites**, and **Recently Viewed** in that order. Guests cannot render or fetch recent history, including on product pages. Successful product-detail reads are recorded only while signed in, using at most six unique IDs under `kvn:recent-products:v2:<memberId>`. Each account has its own browser-local list; the previous mixed guest/device list is not imported. The current product is omitted from its own section. Clear history empties only the current account's list, with an explicit empty state in Account. Invalid/unavailable storage is tolerated; logout/account changes unmount the history view and abort stale card reads; unavailable products are skipped. No profile details are stored in the history list.

Favorites use the existing account's `productLikedBy` relationship. Account changes clear all account-specific heart state and ignore late mutation results. Requests are serialized per product. A failed toggle is never automatically replayed; a non-counting card read reconciles an uncertain result and an error remains visible. If reconciliation also fails, the heart stays disabled and **Check saved state** retries only the non-mutating read before allowing another toggle. Guests receive a sign-in link returning to their current path/query. Auth-dependent catalog resources reload on identity changes.

Review comments render as plain text. Ratings use labeled native radio inputs with keyboard support. Comments require 10–500 trimmed characters; the form includes a count, busy state, recoverable errors and removal confirmation. Public reviews and the private editor load independently. Editing, removal and resubmission preserve hidden moderation state. Only API-confirmed eligible purchases receive a Verified purchase label; the current demo backend returns `false`. Deleted reviews remain in moderation as read-only tombstones and cannot be restored there.

Deployment: provision backend review indexes with `npm run db:maintain` before starting the upgraded backend, then deploy both React builds. The schema-readiness check requires the unique product/member review index. Existing EJS administration is preserved. No payment integration, production database changes, or deployment is part of this work.

## Homepage featured brands

The homepage ends with the reference-style **Featured brands** strip immediately above the shared footer. Nike, adidas, New Balance and Zara use locally hosted black SVG marks with thin dividers and visible keyboard focus. Desktop has four columns; narrow mobile has two columns. The section is rendered by Home only.

Each logo opens `/products?brand=NIKE|ADIDAS|NEW_BALANCE|ZARA`. The catalog sends the same `brand` key to `GET /product/all`, shows the selected brand in its heading and Brand selector, and retains it through pagination, search, collection/size filtering and sorting. Clear all filters returns to the full catalog. A brand with no matching products uses the existing empty state.

Optional `productBrand` is supported in React product create/edit and EJS creation. Existing products with an explicit leading brand name are recognized when metadata is missing; an explicit assignment or unassigned value takes precedence. Generic names need an administrator to assign the brand; photos are not used to guess it. Existing records are not migrated. SVG sources are recorded in [brand assets](media/brands.md).

## Homepage category photos

`CategoryShowcase` uses the supplied reference layout: five square pale blue cards, rounded borders, bottom labels and arrows, and the original heading arrangement. Each entire tile opens `/products?productCollection=...` using the existing CLOTHE, PANTS, HAT, SHOES and OTHERS filters. “Shop all pieces” opens the unfiltered catalog. The section appears only on Home, ahead of the moving outfit Collections row.

Desktop uses five columns, tablet three, and mobile two. All cards retain the same square shape and keyboard focus states. `categoryImages.ts` maps the five supplied transparent PNGs to their matching categories, including `other_essentials.png` for OTHERS. The originals are served locally without editing their pixels or transparency; CSS adjusts their display sizes to account for transparent margins. Images use lazy loading and verified intrinsic dimensions. The rejected editorial stock images are removed. See `docs/media/category-assets.md` for the asset mapping and `docs/media/category-sources.json` for source checksums.

## Moving homepage Collections

`HomeCollections` displays the six outfit products selected in `homeCollectionProducts.ts`, in the reference order (two Zara, two adidas, two Nike sets). It sits after the category links and before New Arrivals. A single `GET /product/cards?ids=...` resolves current public products, images and stock without counting views. Missing/hidden products are skipped; a section-level error can be retried independently, and an empty selection uses the shared empty state. No product records or media are rewritten.

Each white, outlined card contains only the existing transparent product image, the current remaining stock at bottom-left and a circular detail-page link at bottom-right. Names and variant descriptions remain available as image/link accessible labels; prices, categories, favorites and descriptions are not rendered in these cards.

The overflow row advances continuously and wraps through a visual duplicate group. The copy is hidden from assistive technology and excluded from keyboard tab order. Scrolling pauses for hover, keyboard focus, touch interaction, offscreen visibility, inactive tabs and the explicit Pause/Play control. Reduced-motion users receive one manually scrollable group with no autoplay. The native horizontal scroller supports touch and keyboard navigation. Short selections that fit remain static. The smaller Featured Brands section and the existing product carousels remain separate.
